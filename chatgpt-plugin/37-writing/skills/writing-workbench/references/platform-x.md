# X（Twitter）原创写作与线程

## 核心：一个可复述的判断，读者愿意转发或反驳

不要把 X 当公众号摘要箱。先选 **观察/观点、资料发现、实验记录、清单线程、引用评论、长帖** 六种之一。短帖不是单纯删字，它需要比公众号更早亮出判断和证据。

### 三种内容结构

- **单条短帖**：观点/反常观察（1 句）→ 最硬证据（1 句）→ 代价或边界（可选）→ 具体问题（可选）。不要刻意凑四段。
- **线程（Thread）**：第 1 条先给完整价值主张；第 2 条背景；第 3–N 条每条增加新事实/反证/行动；最后给清晰判断和来源链接。每帖即使脱离线程也要能看懂，不强行写“1/10”的流水账。
- **长帖 / X Article**：用长帖承接完整论证，结构可接近一篇短评论；需确认当前账号权限与产品支持，不能假设所有账号都能发 25,000 字长帖或 Article。

### 核心纪律

1. 先明确「这条的可讨论观点」，避免公众号的“从古至今”“我们先来看看”。
2. 使用真实可追溯的截图/链接/数字；没有实际实验不使用「亲测」；没有可查证的数据不制造惊人百分比。
3. 明确引述谁、何时说过；引用评论需要区分被引用者的立场和作者的立场。
4. 以普通短帖 280 加权字符为默认预算；中文通常比纯英文更吃字符。URL 在 X 帖子计数时通常按 23 字符折算。**平台实际编辑器计数为准**。
5. X Premium 的长帖、X Article 等权限、上限随产品变动，必须使用官方说明和当前账号实测；脚本的 `--x-limit` 仅作为设置，不是发布权限核验。
6. 标签 0–2 个自然相关即可；除非用户的账号本来喜欢，否则不复制小红书的 emoji 文风。

### 文件格式与验证

一个 Markdown 文件写线程时，用单独一行 `<!-- POST -->` 分隔每条。**文件中不要加 `# 标题` 或解释性小标题作为实际推文内容**；如需要归档标题，可用 YAML `title` 字段。

```text
第一条：有论点，有读者价值。

<!-- POST -->

第二条：给证据，解释第一条为何成立。
```

ChatGPT Web 交付前需逐帖检查当前平台字符上限、链接折算及结构；不运行 Windows 脚本。

### 获取外部 X 语料的边界

借鉴 [Vink567/twitter-clipper-vink](https://github.com/Vink567/twitter-clipper-vink) 的原文保真：从合法读取的原帖/文章中保留文字、链接与图片次序，不要把自动摘要伪装成剪藏原文。用户未提供权限时不绕过登录、限制或私密内容。剪藏负责归档，不等于允许复制文章发布。
