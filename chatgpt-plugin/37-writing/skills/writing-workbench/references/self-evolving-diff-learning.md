# 选定风格辅助完稿与「AI 初稿 vs 用户手改稿」持续进化机制

本手册专门解决“如何用蒸馏出的风格帮我高效完成初稿（留出我自己修改的空间）”以及“当我改完定稿后，如何让 Skill 自动对比初稿与终稿、不断学习我的真实写作风格进化”。融合了 [SpaceZephyr/creator-buddy](https://github.com/SpaceZephyr/creator-buddy)（`gzh-longform-writer`、`gzh-short-post`、`baokuan-title-generator`）、[dongbeixiaohuo/writing-agent](https://github.com/dongbeixiaohuo/writing-agent)（`edit-diff-learner`）与 [larashero3-dotcom/writing-dna-skill](https://github.com/larashero3-dotcom/writing-dna-skill) 的核心方法论。

---

## 一、 选定风格辅助起草完稿工作流（Co-Drafting for Human Polish）

当用户说“用【某风格】帮我把这篇稿子写出来/写完，我最后自己改”时，Agent 的定位不是替用户包办虚假故事的枪手，而是**帮用户搭好骨架、对齐文风节奏、填实客观论据、并精准标出个人灵魂留白的高级主编助手**。

### 1. 第一步：诊断手头材料，路由六种起草模式（源自 `gzh-longform-writer`）

动笔前先看用户给了什么材料，自动匹配以下 6 种写法之一：

| 用户手头材料状态 | 启用写法模式 | 执行策略与交互动作 |
| :--- | :--- | :--- |
| **1. 只有模糊念头或一句话主题** | **破题 + 访谈式** | 先从反直觉、切身代价、前后对比、行业溯源给出 **5 个差异化切入角度**，并追问 **3 个关键细节问题**（如：你亲身踩过最痛的一个坑是什么？你最想反驳的同行共识是什么？），等用户拍板或直接按最锋利的角度起草。 |
| **2. 想清楚了核心观点，但没展开** | **反模板大纲式** | 先输出带字数配额的章节大纲，强制包含一节**「反面/适用边界（约 300 字）」**防止文章变成片面吹捧，确认或直接按大纲展开全文。 |
| **3. 写了开头或半截草稿卡住了** | **无缝续写式** | 先诊断卡壳原因（是缺转折桥段、缺论据支撑还是结构散了），严格顺着用户已写段落的句长、人称与用词习惯无缝往下续写，绝不推翻用户已经写好的开头。 |
| **4. 丢过来一堆零散笔记/链接/语音转写** | **素材整合式** | 先把每条零散材料压缩成一句话事实账本，提炼出**唯一一条贯穿全文的主线判断（牙齿）**，果断砍掉偏离主线的边角料，重组成文。 |
| **5. 丢过来一篇外部爆款想跟进同题** | **同题异构式** | 拆解原爆款的事实增量，用选定的目标风格 DNA 重新组织切入视角，补充新证据或反向推演，严禁顺着原爆款的段落顺序洗稿。 |
| **6. 已有初稿但觉得味道不对/太像 AI** | **定点手术式** | 先列出 3-5 处核心病灶（开头绕圈、没有具体主语、假例子、结论悬空、句式同构），按选定风格 DNA 重塑句法与节奏。 |

### 2. 第二步：公众号与社媒实战写作护栏（源自 `creator-buddy` `my-voice.md` & `gzh-longform-writer`）

除非目标风格的 `Writing-DNA.md` 另有特殊规定，中文公众号与长帖起草默认遵循以下实战约束：
- **首段独立成立**：微信公众号会自动截取首段作为分享摘要，首段前两句必须直接给出**时间/场景锚点 + 核心反差结论或具体数字**，零寒暄、零“随着……的发展”预热。
- **手机屏呼吸感控制**：
  - **长文（1500-4000 字）**：单段严格控制在 **90 字以内（手机屏约 3-4 行）**，超过 2000 字必须设置信息量明确的小节标题（小标题直接亮判断，不写“一、背景介绍”）。
  - **短贴/短推（≤1000 字）**：单段控制在 **70 字以内（1-3 句）**，优先采用“单点推进式”骨架，全篇少用“你”字说教，多用第一人称“我”分享实测判断。
  - **书斋深度评论（当用户选用厚段散文 DNA 时）**：切换为 200-450 字的厚重段落与多分句长句链。
- **预留「人工灵魂锚点（Human Polish Anchors）」**：
  由于用户明确表示“最后自己去修改”，在起草过程中：
  - 凡是客观事实、逻辑推演、技术拆解、行业对比，直接用高质量母语一气呵成写到位；
  - 凡是涉及**只有用户自己才知道的私人经历、未公开内部数据、或需要用户亲口拍板的强烈个人表态**，严禁由 AI 瞎编，统一插入高亮锚点：
    `> ✍️ **【人工微调锚点 #1 · 个人实历】**：此处建议替换为你实际用这套方案时的 1 个具体场景或踩坑耗时（目前用通用描述占位，你改 2 句话即可瞬间拉满真实感）。`
- **随稿附赠 Top 5 爆款候选标题（源自 `baokuan-title-generator`）**：
  基于 1000 篇 10w+ 爆文规律（字数中位数 22 字，单一强实体 + 数字反差/认知冲突/任务结果），每次交稿在文末附上 5 个不同角色的标题供用户挑选：**① 综合首选版、② 稳健克制版、③ 强传播反差版、④ 搜索长尾版、⑤ 实验悬念版**。

## 二、 用户手改终稿 Diff 持续学习与进化闭环（Self-Evolving Loop）

为什么普通的写作提示词用久了还是每次都要人工改同样的地方？因为它没有把**你动刀改稿的过程（Diff）**沉淀下来。本技能引入了完整的**「初稿存档 -> 手改终稿比对 -> 进化账本更新 -> 自有 DNA 迭代」**闭环。

### 1. 触发时机
- 当你在 AI 辅助生成的初稿基础上自己修改定稿后，把修改后的版本发给 Agent（或者提供本地的两个文件：`ai_draft.md` 和 `user_final.md`），说：*“这是我最后改定的版本，帮我对比学习一下，更新我们自己的公众号风格”*。
- 或者当你直接丢给 Agent 几篇你自己亲手写的最新文章，要求更新自有风格库。

### 2. 自动化 Diff 进化脚本（`scripts/learn_from_user_edits.py`）的工作原理

运行以下命令即可一键完成比对、特征提取、账本更新与语料入库：

```bash
python3 skills/chinese-humanizer-writer/scripts/learn_from_user_edits.py \
  --draft drafts/2026-11-07_ai_draft.md \
  --final drafts/2026-11-07_user_final.md \
  --profile-dir style_profiles/our_own_voice/<自有公众号名称> \
  --apply
```

脚本与 Agent 会从 5 个维度解剖你的手改动作：

1. **词汇斩杀与偏爱词捕获（Lexical Kills & Replacements）**
   - 提取所有在 `ai_draft.md` 中出现、但在 `user_final.md` 中被你删掉或替换的词组与连接词（例如：AI 写了“值得注意的是”、“与此同时”、“赋能”，全被你删了；AI 写了“因此”，被你改成了“所以”或直接删掉）。
   - 自动将这些被删词计入 `evolution_ledger.json` 的 `killed_phrases` 频次表；一旦某个词被你砍掉 ≥2 次，立即自动晋升为自有账号的**永久封杀词（Hard Banned Words）**。
   - 同时捕获你在终稿中新加入的高频特色动词、口癖或行业惯用语，存入 `added_signature_phrases`。
2. **句长与段落颗粒度偏移（Sentence & Paragraph Delta）**
   - 精确计算：`用户终稿平均句长 - AI 初稿平均句长`、`用户终稿平均段长 - AI 初稿平均段长`。
   - 如果你每次都把 AI 80 字的段落拆成两段 40 字的短段，脚本会自动将你自有账号 `Writing-DNA.md` 中的目标段长下调对齐到你的真实舒适区。
3. **标点习惯校准（Punctuation Fingerprint Shift）**
   - 对比初终稿中的破折号 `——`、括号 `（）`、分号 `；`、感叹号 `！`、问号 `？` 数量变化。
   - 例如：如果 AI 初稿用了 0 个感叹号，而你在手改时加了 3 个反问句和 2 处括号吐槽，系统会立即记录*“主创喜欢在段尾用括号补充冷幽默吐槽，且保留适度反问句”*。
4. **结构与开篇/收尾手术分析（Structural Edits）**
   - 重点比对**第一段（前 200 字）**与**最后一段**的改动：你是把 AI 的铺垫全砍了直接从第 3 段开局？还是把结尾的总结段直接删掉了？Agent 会将这一结构偏好凝练为一句话规则写入进化账本。
5. **终稿自动归档入库（Corpus Auto-Ingestion）**
   - 你的手改终稿 `user_final.md` 会自动加上 `track: self` 元数据，存入 `style_profiles/our_own_voice/<自有账号>/raw/` 目录并更新 `00-索引.md`。
   - 因为 Step 6.1 选文机制总是**优先抽取时间最近的 5 篇 `raw/` 原文**来校准语感，所以你每改完一篇文章喂给它，下一次它给你起草新稿时，读取的就是你最新鲜的亲笔定稿！

```json
  ]
}
```
