# 中文审美、表达 DNA 蒸馏与全栈多场景适配指南

如果仅仅删掉 AI 套话，文章可能只是从“啰嗦的机器”变成“干瘪的机器”。要写出真正有质感的中文，必须注入**审美（Taste）**、**表达 DNA（Expression DNA）**与**全栈结构设计**。本指南融合了 [Leonxlnx/taste-skill](https://github.com/leonxlnx/taste-skill)、[alchaincyf/nuwa-skill](https://github.com/alchaincyf/nuwa-skill)、[dongbeixiaohuo/writing-agent](https://github.com/dongbeixiaohuo/writing-agent)、[OUBIGFA/De-AI-Prompt-Enhancer-Writer-Booster-SKILL](https://github.com/oubigfa/de-ai-prompt-enhancer-writer-booster-skill) 与 [hylarucoder/ai-flavor-remover](https://github.com/hylarucoder/ai-flavor-remover) 的核心技法。

## 一、 给 AI 建立中文审美：反统计均值与直白文案铁律（源自 `Leonxlnx/taste-skill`）

大语言模型默认会滑向所有训练语料的“统计平均值（Statistical Mean）”——四平八稳的观点、对称的排比、没有棱角的形容词。[Leonxlnx/taste-skill](https://github.com/leonxlnx/taste-skill/blob/main/skills/taste-skill/SKILL.md) 提出的审美核心是**用独有资产与直白文案（Plain Copy）对抗通用模板**：

1. **竞争对手替换测试（Competitor Swap Test）**
   - 写完一段介绍、评论或产品文案后，把里面的主语换成竞争对手或任意同类事物。如果句子依然完全成立（例如“我们致力于通过前沿技术为用户提供卓越的解决方案”），说明这段话信息量为零，必须重写。
   - 动笔前先盘点 **3-8 个独有事实锚点**（具体版本号、真实门牌街道、精确耗时、踩坑报错码、具体取舍代价），把这些硬事实直接作为句子的主干，而不是挂在形容词后面的装饰。
2. **首段硬事实与动作直给（Lead with Hard Facts & Verbs）**
   - 拒绝在标题和首段玩文字迷雾。首段前两句内必须出现核心名词与至少 1 个硬事实或明确判断。
   - 凡是呼吁行动或总结方案的地方，使用干净的“动词 + 具体宾语”，砍掉一切程度副词（把“极其显著地优化了响应”改为“把响应时间压到 80ms 以内”）。
3. **禁止局部廉价高亮**
   - 不靠满篇加粗、斜体、感叹号或编号徽章（`01 / 02 / 03`）制造重点；真正的重点靠句意本身的反差与具体数字自己跳出来。

## 二、 蒸馏任何人的风格：认知操作系统与 6 维表达 DNA（源自 `alchaincyf/nuwa-skill`）

当用户要求模仿某位作者、或提供了 2-3 段个人历史文章样本时，切忌停留在模仿表面的口头禅（那会变成滑稽模仿秀 Caricature）。按 [alchaincyf/nuwa-skill](https://github.com/alchaincyf/nuwa-skill/blob/main/references/extraction-framework.md) 的架构，从深到浅提取三层特征：

### 1. 深层：心智模型与决策启发式（怎么想）
- **视角镜片**：这位作者习惯从什么维度切入问题？（例如：是先算账本成本、先看历史周期、先拆底层激励机制，还是先看具体的人的处境？）
- **决策直觉（Heuristics）**：提取 `如果遇到 X，优先选择 Y 而非 Z` 的判断偏好。
- **保留内在张力**：真实的人类思考都有矛盾和犹豫（例如既推崇极度理性，又对某种笨拙的坚持抱有温情）。不要把文章写得像滴水不漏的辩论赛机器，保留作者真实的困惑、边界感与“这件事我还没想明白”的诚实。

### 2. 表层：6 项量化句式指纹（怎么写）
在分析用户提供的样本时，快速扫描并对齐以下 6 项量化指标：

| 指纹维度 | 测量与观察指标 | 人类高质感区间参考 | AI 默认退化区间（需规避） |
| :--- | :--- | :--- | :--- |
| **1. 句长分布与标准差** | 平均句长（字/句）及长短句标准差 | 句长标准差 ≥ 4.5；35 字以上多重复句与 10 字以内短判断句交错 | 句长集中在 18-25 字，标准差 ≈ 1.2，像节拍器一样匀速 |
| **2. 疑问与设问比例** | 每千字真问题（非自问自答套路）的数量 | 用于推动思考深化的真问题，问而不立刻给标准答案 | 滥用“那么问题来了？”、“为什么这么说呢？”清嗓式假设问 |
| **3. 类比与隐喻密度** | 每千字比喻数量及取材领域 | 每千字 ≤ 2 个，取材于作者熟悉的特定物理/生活经验，一句即止 | 每段都在打比方，且海洋、战争、机器、植物比喻混用 |
| **4. 视角与人称锚定** | 第一人称“我/我们”与第二人称“你”的分布 | 观点处用“我”承担责任，场景处用“你”拉近读者，事实处隐去人称 | 通篇上帝视角抽离旁白（“人们往往认为”、“不难发现”） |
| **5. 确定性情态比** | 绝对词（一定/必然/毫无无疑）vs 审慎词（大概/恐怕/未必） | 结论果断，但对复杂因果保持审慎限定（“未必”、“多半”） | 满篇“毋庸置疑”、“绝对”，或者满篇“也许可能在一定程度上” |
| **6. 标点生态指纹** | 分号 `；`、冒号 `：`、括号 `（）`、感叹号 `！` 的使用率 | 善用分号组织并列复句，善用括号补充冷幽默或吐嘈，极少用感叹号 | 滥用破折号 `——`、引号 `“”`（给普通词加引号）和感叹号 |

## 三、 全栈深度长文工作流与厚段长句链（源自 `writing-agent` 与 `OUBIGFA`）

当处于 `writer-booster`（深度原创/评论随笔模式）时，融合 [dongbeixiaohuo/writing-agent](https://github.com/dongbeixiaohuo/writing-agent) 的全栈流水线与 [OUBIGFA/De-AI-Prompt-Enhancer-Writer-Booster-SKILL](https://github.com/oubigfa/de-ai-prompt-enhancer-writer-booster-skill/blob/main/good-writing/references/style-dna.md) 的文体工程规则：

### 1. 动笔前先定“牙齿（Position）”与“伤疤素材（Scar Tissue）”
- **立意带牙齿**：动笔前先用一句话写出本文具有排他性的核心判断（如果一句话反过来讲没人会反对，比如“技术创新需要兼顾安全与效率”，那就是没有牙齿的正确的废话）。
- **打捞伤疤细节**：舍弃四平八稳的行业通识，优先使用真实的失败教训、隐秘成本、反直觉数据或具体业务冲突作为开篇切入点。

### 2. 反模板大纲与“大纲测试”破局
- **反对称大纲（Outline Anti-Template）**：全文编号列表或项目符号列表**最多不超过 1 处**；相邻两个小节严禁采用相同的内部结构（不能每一节都是“观点 -> 案例 -> 总结”）。
- **打破大纲测试（Outline Test）**：如果把文章每一段的第一句话抽出来连在一起，刚好是一份工整的提纲，说明这是典型的机器扩写文。破局方法：**从具体场景、反常数据或历史细节切入段落，把核心论点压到段中或段尾浮现**。
- **中段意外转折**：在文章 50%-70% 处引入一个开头无法直接预测到的深层约束、反面视角或代价拆解，打破“现象 -> 原因 -> 对策 -> 展望”的线性套路。

### 3. “厚重的思想砖块”与多分句长句链（针对评论/随笔/杂文）
- **拒绝碎段子弹流**：深度评论控制在 4-8 个自然段（或每节包含 200-450 字的厚重段落），在一段之内通过逗号 `,` 和分号 `;` 编织完整的论证链条（例如在一段内一气呵成完成“现象白描 -> 揭示荒谬处 -> 历史或跨界参照 -> 冷峻判断”）。
- **不对称长句链**：用 `A 固然……；然而一旦考虑到 B，那种关于 C 的乐观想象便很难成立` 这样有纵深感的不对称复句，取代工整肤浅的 `不是 A，而是 B`。
- **三层语体配比（7:2:1 黄金律）**：
  - **70% 现代平实书面语**：准确、干净、主谓宾清晰。
  - **20% 凝练文言虚词/双音节词点缀**（仅限深度评论/随笔）：在关键转折或收束处适度使用 `未尝不、固然、诚然、大抵、罢了、何尝、动辄、寥若晨星`，瞬间拉开与翻译腔的距离（注意核查虚词语义方向，切勿误用）。
  - **10% 克制的白话冷刺**：用括号或短句插入一句平实的常识反讽，绝不用“家人们、绝绝子、被喷惨了、爽了一把”等廉价网络俚语。
- **情绪压进事实**：整篇零感叹号，严禁写“令人心痛、发人深省、不禁让人感叹”，而是把冲突的事实并置在一起，让读者自己感到荒诞或震动。

## 四、 隐性逻辑过渡词库（源自 `hylarucoder/ai-flavor-remover`）

彻底扔掉“首先、其次、再次、最后、此外、综上所述、总而言之”。当段落之间需要衔接时，改用以下符合中文母语思维流的隐性连接方式：

| 逻辑关系 | 严禁使用的 AI 机械路标词 | 推荐替换的母语自然过渡表达 |
| :--- | :--- | :--- |
| **递进与深挖** | 此外、不仅如此、更进一步地说、值得注意的是 | 往深里看、顺着这个逻辑往下推、更麻烦的是、真正棘手的地方在于、还不止于此 |
| **转折与反拨** | 然而、不可否认的是、尽管如此、硬币的另一面是 | 话虽这么说、反过来想、但实际落到执行上、偏偏事与愿违、可问题就在这儿 |
| **举例与落脚** | 例如、具体而言、以 X 为例我们可以看到 | 拿 X 来说、不妨看个具体的例子、最典型的就是、落到日常场景里 |
| **回溯与转换视角** | 基于以上分析、回到我们最初的问题、从另一个角度来看 | 说到这儿、回过头来看、换个账本算一下、跳出技术细节看一眼 |
| **收束与定音** | 综上所述、总而言之、一言以蔽之、由此可见 | 说到底、归结起来就一条、把账算清楚之后、到这一步事情就很明白了 |

## 五、 五大高频写作场景适配护栏（Scene Guardrails）

不同文体对“人味”的定义截然不同，动笔前必须按目标场景切换护栏（源自 [MrGeDiao/shuorenhua](https://github.com/MrGeDiao/shuorenhua) 与 [op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh)）：

| 场景类别 | 核心语域与结构策略 | 严禁触碰的红线 |
| :--- | :--- | :--- |
| **1. 公众号 / 商业科技深度长文** | 开篇用具体反常案例或硬数据破题；中段用厚重段落展开因果推演；小标题用陈述句亮出具体判断（拒绝四字对称词）。 | 严禁“随着……的发展”开篇；严禁全文超过 1 处编号列表；严禁编造第一人称故事。 |
| **2. 个人随笔 / 杂文 / 读书笔记** | 保留作者的个人视角、犹豫感、局部吐槽与独特审美；允许长句链与冷峻短句交替；保持 7:2:1 语体张力。 | 严禁喊口号升华结尾；严禁心理鸡汤“接住体”；严禁替作者强行拔高情绪。 |
| **3. 小红书 / X (Twitter) 社媒贴** | 第一句直给高密度痛点、反常识结论或实测结果；多用短自然段与动词；讲人话、给干货清单或真实踩坑复盘。 | 严禁客服腔开场白；严禁空洞无物的正确的废话；严禁AI式伪互动（“评论区告诉我哦”）。 |
| **4. 技术文档 / API 说明 / Release Notes / FAQ** | 极致准确、平实、中立；FAQ 必须第一句直给结论或操作动作；保留必要的工程术语与条件连接词（`如果/否则/当……时`）。 | **严禁把执行前条件和风险警告挪到操作步骤之后**；严禁改动代码块、命令、参数名与版本号。 |
| **5. 学术论文 / 行业研究报告** | 保持客观严谨的学术书面白话；通过消除欧化长定语（层叠“的”）、还原冗余虚化动词（`进行研究 -> 研究`）和砍掉空洞套话来降 AI 率。 | 严禁口语化或加入网梗；严禁篡改显著性水平、样本量、文献归因与不确定情态（`可能/提示/相关`）。 |
