# 小红书：搜索型、可扫读的真实经验笔记

## 成立条件

在前三行让对的人看明白：这条写给谁、解决什么具体麻烦、为什么值得看。图片、封面与正文是一个承诺；图片没有提供的真实使用结果，正文也不能编造。

### 先判七种类型

1. 种草测评：有自己真实使用体验才写亲测，并具体列出不适合人群。
2. 干货教程：每一步写动作、输入、输出和失败处理，而不是光给口号。
3. 个人经历：未经用户提供不得编造“我花了一个月/第一次试就赚了钱”。
4. 合集清单：确保标题数字与正文项目一致。
5. 避雷拔草：指名评价要有事实依据，避免未证实的商品/品牌诽谤。
6. 工具/好物分享：同一对象给出明确的使用场景、缺点和价位的来源时点。
7. 经验复盘：明确哪里失败、代价多少、什么时候发生、下一次会怎么做。

### 三层结构

- **标题**：核心可搜索词 + 人群/场景 + 结果或真实差异。可参考社区常见的 20 字短标题写法，但**不要把 20 当作静态永久的平台官方规范**；用当前编辑器确认。
- **开头三行**：首先写用户在意的结果或代价，其次给可核验的细节，再预告马上能得到什么。没数据不要凑数字。
- **正文**：可扫读的小段落/步骤图文/结尾一个有明确对象的问题。搜索词自然放在标题、首段、内容重点与适当标签中，不机械刷标签。

### 图文方案（由作者/设计工具执行）

- 封面：只做一个视觉承诺（问题、效果、对比或清单）。
- 内页：若是教程，一张图只讲一个动作，配图编号与正文同序；若是历史知识卡，则一张图只承载一个核实事实。
- 文案：Emoji 是可选节奏器，服从账号 DNA，不强制 8–15 个；大量营销感表情会伤害可信度。
- 标签：建议提供 1 个主搜索词、2–4 个具体相关标签候选；编辑器最终选词由人工确认。

### 商业/信任检查

- 真实合作、赠品、联盟营销等关系，需要符合平台当前的商业披露规则。不能用“纯分享”掩盖付费关系。
- 不能捏造体重变化、疾病疗效、投资收益、购物优惠、库存、功效对比与用户证言。
- 不要承诺“照做一定成功”，推荐有条件时附适用边界。

### 输出默认

标题 3 个（搜索型、情绪型、反差型） + 正文 + 首屏三行说明 + 标签候选 + 封面标题/图卡结构 + 风险备注。用户只需一篇正文时删减附加信息。

ChatGPT Web 交付前手工核对标题兑现、首屏承诺、标签相关性与真实体验；不运行 Windows 脚本。
