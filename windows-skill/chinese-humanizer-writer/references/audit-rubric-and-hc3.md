# 多维审查量表、12 项清零清单与 HC3 语言学检测基准

在文稿交付前，必须通过本手册的三重质量门禁：**HC3 语言学底层特征校准**、**12 项交付前快速清零检查**、**50 分制五维评分量表**以及**事实账本双向核对清单**。本手册融合了 [hardikpandya/stop-slop](https://github.com/hardikpandya/stop-slop/blob/main/SKILL.md)、[Hello-SimpleAI/chatgpt-comparison-detection](https://github.com/hello-simpleai/chatgpt-comparison-detection/blob/main/HC3/README.md)（HC3 语料库）、[op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh/blob/main/SKILL.md) 与 [MrGeDiao/shuorenhua](https://github.com/MrGeDiao/shuorenhua) 的审查标准。

## 一、 HC3 中文人机对比语言学特征基准（源自 `Hello-SimpleAI/chatgpt-comparison-detection`）

根据 [HC3 人类与 ChatGPT 对比语料库研究](https://github.com/hello-simpleai/chatgpt-comparison-detection) 对上万条中文问答的语言学统计，AI 文本之所以一眼假、且哪怕删掉表面提示词仍会被 RoBERTa 检测器识别，根源在于以下 5 项深层分布特征。改写与创作时必须主动向人类专家区间对齐：

| 语言学维度 | AI 默认生成特征（高危暴露区） | 人类母语专家特征（目标校准区） | 实操修正策略 |
| :--- | :--- | :--- | :--- |
| **1. 篇幅与词汇密度 ($D$)** | 篇幅冗长（平均是人类的 1.8-2 倍），但用词高度重复、词汇密度极低，喜欢把一句话拆成三句车轱辘话。 | 篇幅精悍，词汇丰富度高，一句话包含高密度实词与具体概念。 | 砍掉同义重复句，用高信息密度的实词替换空泛解释，字数宁少勿水。 |
| **2. 词性分布（POS）** | 名词（NOUN）、形容词（ADJ）、限定词（DET）与并列连词（CCONJ）占比极高，呈现僵硬的“论文说明书体”。 | 动词（VERB）、副词（ADV，指汉语中精准表状态/语气的单双音节词如`偏偏、索性、恰好`）与句内标点占比更高。 | 把名词化结构还原为动词，删掉冗余形容词，用准确的动作链推动句子。 |
| **3. 句法依存距离** | 并列关系（`conj`）依存距离极短，酷爱用工整对称的四字词或短语并列（`A 和 B`、`X、Y 与 Z`）。 | 句法结构富于不对称变化，多用流水句、递进兼语句与跨分句长依存。 | 拆掉工整的短并列与三段式，改用分号或逗号连接的不对称复句。 |
| **4. 情感极性分布** | 高度中立（Neutral）或无脑积极“正能量”，几乎不出现负面判断、吐槽或悲观审慎态度。 | 包含真实的情感起伏、锋利的批评、合理的怀疑、犹豫或冷幽默。 | 在评论与随笔中保留作者真实的批评锋芒、局限坦白与反讽，拒绝和稀泥。 |
| **5. 困惑度（PPL）分布** | 全文与单句 PPL 极低且高度集中，永远选择统计概率最高的平庸搭配（如`发挥着不可替代的作用`）。 | PPL 呈现长尾分布，平实叙述中偶尔跳出高 PPL 的鲜活动词、具象细节或独特比喻。 | 替换掉闭着眼都能猜出下半句的陈词滥调，在关键处使用具体、鲜活的动词与细节。 |

## 二、 12 项交付前快速清零自检清单（源自 `hardikpandya/stop-slop` 中文适配版）

成稿后逐条扫描，发现任何一项立即动刀修正：

- [ ] **1. 查空挂修饰副词**：有没有“非常、极其、深刻地、全方位地、真正地、彻底地、毫无疑问地”？全部删掉，让事实和动词自己说话。
- [ ] **2. 查翻译腔被动与虚化动词**：有没有连续的“被……”或“进行了 X / 实现了 Y 的提升”？找出具体施事者作主语，还原为直接动词。
- [ ] **3. 查无生命物体做人类动作**：有没有“数据告诉我们”、“时代要求我们”、“投诉变成了补丁”？换成具体的人或团队。
- [ ] **4. 查清嗓式预告与元路标**：有没有“值得注意的是”、“不难发现”、“接下来我们将探讨”、“如前文所述”？直接删掉。
- [ ] **5. 查虚假二元对比**：有没有不承担纠偏功能的“不是 X，而是 Y”或“不仅……更……”？删掉前半句否定铺垫，直接说 Y。
- [ ] **6. 查三段式排比与连续等长句**：有没有连续三句话字数相近、句首相同，或者强行凑够三个并列形容词/四字成语？打断其中一句或合并为两项。
- [ ] **7. 查段尾拔高金句**：段落结尾是不是有一句刻意制造的升华口号（“这才是真正的 X”、“未来已来”、“让我们拭目以待”）？直接砍掉。
- [ ] **8. 查破折号滥用**：有没有用 `——` 当首句起手、单段出现 ≥2 次破折号、或跨段连续用破折号？改为逗号、句号或括号。
- [ ] **9. 查空洞宣告句**：有没有“原因是结构性的”、“影响是深远的”、“意义是重大的”却不写具体是什么原因、什么影响？直接换成具体内容。
- [ ] **10. 查上帝视角抽离旁白**：有没有高高在上的“人们往往会……”、“在这个快节奏的社会中”？把视角拉回具体的业务现场或“你/我们”。
- [ ] **11. 查同义词躲避与生造黑话**：有没有在相邻三句话里把同一个词强行换成三个近义词，或者生造带引号的“X-Y-Z 一体化闭环”？还原为自然重复的准确词。
- [ ] **12. 查装饰性排版噪音**：有没有满篇乱飞的粗体词、每项必带 `**标签：**` 的假列表、以及非社媒文稿里的标题 Emoji？全部清理干净。

## 三、 50 分制五维质量审查量表（50-Point Scoring Rubric）

对完成改写或起草的文稿按以下 5 个维度打分（每项 1-10 分，满分 50 分）。**硬性门禁：总分低于 40/50（或任一单项低于 7 分）严禁交付，必须回炉重修！**

| 评估维度 | 核心核查问题 | 1-4 分（严重 AI 味，重度返工） | 5-7 分（仍有机器残留，需局部精修） | 8-10 分（母语专家级质感，准予交付） |
| :--- | :--- | :--- | :--- | :--- |
| **1. 直接性 (Directness)** | 是直接陈述事实与判断，还是在不停清嗓子、预告和铺垫？ | 满篇“随着……的发展”、“值得注意的是”、“不是A而是B”，绕三圈才进正题。 | 删掉了明显套话，但首段仍偏空泛，部分段落开头仍有机械过渡词。 | 开门见山，句句给增量信息，零预告、零清嗓、零自我指涉。 |
| **2. 节奏感 (Rhythm)** | 句长与段落呼吸是否自然多变，还是像节拍器一样单调对称？ | 句长高度雷同，满篇三段式排比、四字成语堆砌与机械项目符号列表。 | 有长短句变化，但偶尔出现连续“她/它……”复读或段尾升华短句。 | 长短句标准差大，厚重长句链与利落短句交错，读出声来极度顺畅。 |
| **3. 信任度 (Trust)** | 是否尊重读者智商，还是在搞保姆式解释、爹味说教与强行点题？ | 讲完例子还要加一句“这深刻揭示了……”，给普通词乱加引号和粗体。 | 较少说教，但偶尔忍不住在段尾总结升华或用副词强行强调重点。 | 展示事实而非说教（Show, don't tell），点到即止，信任读者的理解力。 |
| **4. 真实感 (Authenticity)** | 听起来像有具体处境的真人写的，还是统计平均出来的硅基公文？ | 充斥“赋能、抓手、至关重要、织锦”或伪造的“凉咖啡雨夜”鸡汤。 | 词汇平实，但语气过于四平八稳、绝对中立，缺乏人类的具体视角。 | 语域贴合场景，用词鲜活准确，保留了恰当的锋芒、克制或业务现场感。 |
| **5. 信息密度 (Density)** | 删掉任何一句话或一个词，信息量会受损吗？还有水分可挤吗？ | 50% 以上是车轱辘话、同义复述、空洞形容词与虚化动词外壳。 | 信息较扎实，但仍存在少量“进行了 X”、“起到了 Y 作用”等冗余结构。 | 字字有落脚，无一句废话，无一处同义水词，信息密度极高。 |

## 四、 事实账本与结构保护双向核对清单（Fact & Structure Guardrail）

在交付改写稿前的最后一秒，必须对照原稿逐项核对以下 6 条红线（源自 [op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh/blob/main/SKILL.md) 与 [MrGeDiao/shuorenhua](https://github.com/MrGeDiao/shuorenhua)），**任何一条不通过即判定为 L1 级严重事故，必须立即回滚修正**：

1. **零新增幻觉核对**：改写稿中是否出现了原稿没有的数字、百分比、年份、人名、机构名、第一人称亲历故事或生活布景？
2. **零事实遗漏核对**：在合并三段式排比或把列表转散文时，是否不小心删掉了原稿中独立的业务功能、并列条件、排序先后或“同时发生”的关系？
3. **确定性与情态锁定核对**：原稿中的 `可能、大概、有望、计划、正在、拟、据称、被认为、超过、不低于、仅在……时` 等限定词，是否被篡改成了已完成或绝对确定的表述？
4. **无源引用保护核对**：原稿中的 `研究表明、专家指出` 等无出处论断，是否保留了其归因局限？（严禁只删掉“专家指出”而把无源观点变成裸事实，也严禁编造假论文出处）。
5. **代码与专有名词冻结核对**：代码块、行内代码、CLI 命令、文件路径、URL、版本号、API 字段名、表格数值是否与原稿 100% 逐字一致？
6. **逻辑顺序与安全警告核对**：在技术文档或操作指南中，前置条件（Prerequisites）与风险警告（Warnings）是否仍然严格位于操作动作之前？
