# 2026-11-07 研究基线

## 候选与结论

1. **EMNLP 2026** — [Evaluating Style-Personalized Text Generation: Challenges and Directions](https://aclanthology.org/2026.emnlp-main.168/)。多评价器组合比单一 BLEU/embedding/模型判断更稳健。**采纳理念**：个人文风评估采用事实保真+风格+真人复核，不迷信一个分数；尚未证明本项目具体增益。
2. **2026** — [How LLMs Distort Our Written Language](https://arxiv.org/abs/2603.18161)。强调编辑过程中意义漂移。**采纳理念**：改稿必须检查论点、确定性词、数据和立场是否改变。
3. **2026** — [PerFine: Iterative Refinement for Personalized Text Generation](https://aclanthology.org/2026.aacl-long.37.pdf)。提出结构化反馈与迭代策略。**候选**：可比较 1–3 轮结构化批评+改写与一次性改写；未做本项目实测，不默认无限迭代。
4. **开源工程** — [sansheng-write](https://github.com/sanshengai/sansheng-write)：阶段化公众号流程、标题、排版；**候选**：借鉴分阶段门禁，避免未经授权复制模板代码。
5. **开源工程** — [SpaceZephyr/creator-buddy](https://github.com/SpaceZephyr/creator-buddy)、[larashero3-dotcom/writing-dna-skill](https://github.com/larashero3-dotcom/writing-dna-skill)：平台细分与风格 DNA。**已体现在 v3 框架**。

## 日更质量门禁

- 每篇新来源至少记录 URL、作者/机构、时间、原始主张与我们自己的推断。
- GitHub 只能把可验证的 Stars/增长区间当热度证据；不能凭一个 star 总数断言新晋热门。
- 不复制来源文章长文或作者个人故事；以许可与出处约束具体代码引用。
- 研究增量不足时直接记录“没有值得升级的改动”。
- 修改必须说明为何优于原规则、有何反例、怎么测，以及失败后的回滚策略。
